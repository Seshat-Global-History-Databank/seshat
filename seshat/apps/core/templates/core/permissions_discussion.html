Extremely Important Questions and points for discussion:

Public vs. Not Public Data: Definitions and Criteria  Peter   Jenny   Pieter 

Public Data
  • Visible and accessible to anyone. Yes
  • Can be downloaded in CSV format or accessed via API. Yes
  • Free to use without restrictions. No, anybody using our data mus follow the citations procedure.
  • Seshat Experts can see and download it but cannot share it publicly. After signing the form. The wording should be broader than just ‘sharing’. They should also not yet use it for their own publications and we need to make clear to them that these data are still under construction.
Not Public Data
  • Visible and accessible only to the internal team.
  • Can be downloaded in CSV format and used by us.
  • Seshat Experts can see and download it but cannot share it publicly.
  • Not public data are those on which our team currently works.
What Defines Public Data?
Seshat data becomes public when an article using these variables is published (typically, initially as a SocArxiv preprint). At the same time, we publish the replication dataset here. Public data may include instances, which have not yet been well coded and/or expert reviewed, because we want to get feedback on them. But this should be clearly marked.


Some key questions:

1. Is public data defined by expert review?

No Maybe it's better to think about it as being defined by our own "curation". I don't think we could claim every code and description in the Equinox-2020 dataset has been reviewed by experts, but we underwent our own review and cleaning process before making the decision to release the data. Likewise, the Cliopatria shapes are publicly available but haven't yet been through expert review.

2. Should public data be limited to what has been used in our publications?

Yes No, I don't think so. @Turchin, Peter the Equinox-2020 dataset includes data that haven't been used in specific publications, right? And for the upcoming Polaris release, we don't have to be constrained by which data have gone into our articles.

If so, does that mean all unpublished data remains private indefinitely?

Unless we decide to release it, but the general rule is that only data used in publications becomes public.

3. What happens when new data is added to public sections?

This is a question I also have. Ideally, I think they would be default private, and we can decide to publish them using a button.
So we'll need to clearly mark public and private data. How about a small coloured badge like the current ones indicating "Confident", "Inferred"?
  • If Jakob enters new data into the public parts of the database, does it automatically become public?
  • Do we want it to become public only after Experts review it?
    • If it is a variable that was marked as public, then new data points added are also public.
  • Do we need an approval process before making newly added data publicly accessible? This is done at the same time when we post the article on these data.

We need to clarify these points to ensure consistent data-sharing policies.
